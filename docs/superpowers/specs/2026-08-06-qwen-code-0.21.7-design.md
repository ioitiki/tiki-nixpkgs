# Qwen Code 0.21.7 Package Design

## Goal

Add Qwen Code 0.21.7 as a directly buildable package in this flake. The package
must expose the `qwen` command on both Linux systems already supported by the
flake: `x86_64-linux` and `aarch64-linux`.

## Package structure

Create `packages/qwen-code/package.nix` as a binary derivation using the
official standalone archives published with the upstream v0.21.7 release. A
platform map will select the matching Linux x64 or Linux arm64 archive and its
fixed hash. Unsupported platforms will fail evaluation with a clear message.

The archive already contains the JavaScript bundle, native modules, a private
Node.js runtime, bundled skills, web assets, and its `bin/qwen` launcher. The
derivation will install this complete tree under `$out`, preserving the layout
expected by the launcher. `autoPatchelfHook` will make the bundled ELF runtime
and native modules usable in the Nix store; the derivation will provide only
the runtime libraries reported as required by those files.

The package metadata will identify Qwen Code, the Apache 2.0 license, the
upstream repository and release changelog, `qwen` as the main program, and the
two supported Linux platforms.

## Flake exposure

Add `qwen-code` to the default overlay with `callPackage`, then inherit it from
the per-system package set. This makes `nix build .#qwen-code` and downstream
overlay consumption work consistently with the repository's other packages.
The existing unrelated `flake.nix` edits will be preserved.

## Validation

The derivation will run an install check using an isolated writable home and
`qwen --version`. Final verification will evaluate the exported version, build
`.#qwen-code` without creating a result symlink, execute the built command's
version path, and run the flake's no-build check.

## Non-goals

This change will not rebuild the upstream TypeScript monorepo, add an updater,
modify NixOS configuration, activate the package on a live system, or alter any
existing package derivation.
